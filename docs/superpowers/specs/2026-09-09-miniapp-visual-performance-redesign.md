# 家压小程序视觉与交互性能改造设计

日期：2026-09-09  
状态：待用户确认  
视觉基准：用户提供的八屏家压小程序设计稿

## 1. 目标

在不改变现有业务接口、数据库结构和核心页面路径的前提下，将当前小程序升级为统一、清晰、适合家庭健康场景的产品界面，同时解决页面切换闪烁、重复请求、按钮反馈迟缓和列表渲染卡顿。

验收目标：

- 核心页面在视觉上与参考设计稿属于同一套产品语言。
- 首页、家庭、录入和历史页面切换时不出现明显白屏或内容跳动。
- 用户点击主要操作后 100ms 内获得按压、加载或禁用反馈。
- 快速切换成员和时间范围时，旧请求不能覆盖当前页面数据。
- 普通模式与长辈模式均保持清晰、可点击和可读。

## 2. 设计方向

设计判断：面向家庭健康管理的微信小程序，使用温和、可信赖、低认知负担的浅绿色视觉语言。

- 设计变化度：4/10。保持规整与稳定，避免过度装饰。
- 动效强度：3/10。动效只用于状态反馈和内容过渡。
- 信息密度：5/10。满足健康数据展示，但保持足够留白。
- 主题：全局浅色，不在页面间切换深浅主题。
- 品牌色：健康绿为唯一主强调色；橙色仅表示偏高或提醒，红色仅表示高风险。

## 3. 视觉系统

### 3.1 色彩

- 页面背景：浅灰绿 `#F5FAF7`。
- 卡片背景：白色 `#FFFFFF`，必要时使用浅绿 `#ECF8F1` 表示健康状态。
- 主色：`#09A86B`，按下状态使用更深绿色。
- 主文字：深青黑 `#12342F`。
- 次文字：中性灰绿，确保与背景达到可读对比度。
- 正常、关注、高血压状态保持绿色、橙色、红色的固定语义。

### 3.2 字体与间距

- 页面标题、血压读数、成员姓名建立明确的三级字号体系。
- 正文不低于小程序等效 14px；长辈模式关键正文和操作增大一级。
- 使用 8px 基础间距网格，页面水平安全边距保持一致。
- 主要触控区域高度不低于 44px，重要按钮不低于 48px。

### 3.3 形状与层级

- 采用统一的 12px、16px 两档圆角；胶囊形状仅用于状态标签和主按钮。
- 卡片主要依靠背景与间距分层，阴影保持轻量，避免多层阴影影响性能。
- 不使用纯文本字符充当功能图标；采用统一的本地图标资源。
- 头像、状态标签、输入框和按钮由共享组件统一控制视觉状态。

## 4. 两轮改造范围

### 4.1 第一轮：核心闭环

页面：

1. 登录与启动体验
2. 首页家庭概览
3. 血压记录
4. 历史与趋势
5. 家庭管理

重点：

- 登录页减少无效留白，强化品牌、说明和主操作。
- 首页突出当前成员、最近血压、状态和常用入口。
- 成员头像横向切换保持轻量，当前成员反馈清晰。
- 录入页使用大尺寸数字输入、固定单位、实时校验和明确保存状态。
- 历史页统一时间范围切换、统计卡、趋势图和记录列表。
- 家庭页提供简洁的成员列表、身份信息、权限入口和添加成员操作。

### 4.2 第二轮：辅助功能与完整状态

页面：

1. 数据解读
2. 提醒设置
3. 个人中心
4. 成员资料与新增成员
5. 全局空状态、错误状态、加载状态和弱网重试

重点：

- 数据解读按状态、参考范围和健康建议组织信息。
- 提醒设置使用即时反馈开关，失败时回滚并提示。
- 个人中心保持轻量，不显示开发阶段版本文案。
- 表单页面统一字段、选择器、错误提示和保存反馈。

## 5. 组件设计

优先建立以下共享组件，页面不重复定义相同样式：

- `PageShell`：页面背景、安全区和统一内边距。
- `AppHeader`：标题、返回、右侧操作。
- `HealthCard`：基础卡片和浅绿状态卡变体。
- `ProfileSwitcher`：成员头像、名称和选中状态。
- `BloodPressureReading`：收缩压、舒张压、单位与状态。
- `SegmentedControl`：手动输入、设备同步及时间范围切换。
- `FormField`：标签、输入、单位、错误和辅助说明。
- `StateView`：骨架、空状态、错误和重试。
- `ActionButton`：普通、加载、禁用和按压状态。

组件必须支持普通模式与长辈模式，业务页面只传递内容和状态。

## 6. 交互与性能设计

### 6.1 数据加载

- 成员列表和当前成员摘要采用短时缓存；返回页面时先显示已有数据，再后台刷新。
- 同一页面同一参数的并发请求去重。
- 快速切换成员或时间范围时，以请求序号或取消标记阻止旧响应写回。
- 页面首次加载使用与最终布局等高的骨架，避免布局跳动。
- 局部接口失败只影响对应区域，不清空整个页面。

### 6.2 操作反馈

- 所有主要按钮在提交期间禁用并显示加载状态，防止重复提交。
- 开关和分段选择先立即反馈；服务端失败时回滚并显示原因。
- 页面跳转入口提供按压态，避免用户误认为点击无效。
- 成功操作优先局部更新，再按需要后台刷新，减少整页重载。

### 6.3 渲染控制

- 稳定列表 `key`，缓存只依赖输入的成员卡和记录行。
- 避免在渲染过程中重复筛选和创建大型对象。
- 趋势图只渲染当前时间范围数据，避免无意义动画。
- 动画限于透明度、位移和缩放，不动画阴影、模糊或大面积渐变。

## 7. 页面状态与错误处理

每个数据页面必须具备：

- 首次加载骨架。
- 有缓存时的静默刷新状态。
- 无数据时的解释与下一步操作。
- 可恢复错误的重试入口。
- 登录失效时统一清理会话并返回登录页。
- 保存失败时保留用户输入，不重置表单。

## 8. 素材策略

- 参考稿中的人物家庭插画不直接复制，制作风格相近但独立的启动页插画。
- 图标使用统一线宽的本地资源，避免依赖运行时网络字体。
- 头像优先显示用户上传内容，无头像时使用一致的插画头像或姓名首字占位。

## 9. 测试与验收

自动化测试：

- 组件的加载、禁用、错误和长辈模式。
- 成员切换、时间范围切换和异步竞态。
- 表单校验、重复提交和失败后输入保留。
- 缓存命中、后台刷新和局部降级。

人工验收：

- 微信开发者工具常见 iPhone 尺寸下逐页对照设计稿。
- 检查底部安全区、长文本、空数据、弱网和连续快速点击。
- 使用开发者工具性能面板检查重复请求和长任务。
- 确认所有核心页面均无明显白屏、闪烁和触控延迟。

## 10. 边界

本次改造不包含：

- 修改服务端业务规则或数据库结构。
- 新增设备蓝牙同步能力。
- 医疗诊断或治疗建议。
- 完全复刻参考稿中可能受版权保护的人物插画。
- 增加与两轮页面体验无关的新业务模块。
